## 技術考量

### 專案管理
- 專案資料需要儲存在 localStorage 和 Google Drive
- 專案與會議的關聯關係（一個專案可以有多個會議）
- 專案選擇 UI 的設計（下拉選單 vs 卡片選擇）

### Item 留言
- 留言資料結構設計（巢狀在 item 中）
- 留言的即時同步機制
- 留言的編輯/刪除權限控制
- 大量留言的效能考量（是否需要分頁）

### Google Drive 同步
- 持續同步的效能考量（避免頻繁 API 呼叫）
- Token 過期處理機制（自動重新授權）
- 衝突解決策略（最後寫入優先 vs 時間戳記優先）
- 大量資料的增量同步機制
- 離線狀態下的同步佇列管理

### 會議資料匯入與恢復
- 資料格式驗證和錯誤處理
- 匯入資料的向後兼容性
- 重新開始會議時的資料清理策略
- 匯入大量資料的效能考量

---

## 優先順序建議

1. **Google Drive 同步機制改進** - 提升資料可靠性和使用者體驗
2. **會議資料匯入與恢復** - 增強資料管理能力
3. **Item 留言** - 需要考慮資料結構和同步機制
4. **專案管理** - 功能較複雜，需要較多規劃

---

## 備註

- 所有功能實作前需要更新 `spec/data-structure.md` 定義資料結構
- 需要考慮向後兼容性（現有資料的遷移）
- P2P 模式下的即時同步需要確保資料一致性
- UI 設計需要參考 `spec/ui-design.md` 的設計規範
